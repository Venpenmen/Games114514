# 《忍者之夜》美术素材制作清单 v1.0

> 2026-11-16。对应 [ART_DIRECTION.md](ART_DIRECTION.md) 五轮冻结美术规范；此处仅为**制作计划与验收清单**，不代表素材已制作。将作品分为**原画资产 / 图形 UI / 程序化动效 / 后续公共音频插件**，避免将编程实现误列为图片资源。不得直接复制原版游戏的美术资源。
> 先制作最小视觉样张，确认美术语言后才规模化生产。最终数量须在 UI 原型和具体游戏数据表审查后定稿；这里提供**建议制作单位与数量，不伪称原版官方艺术配件清单**。

## A. 第一批：用来审查风格的最小原型（P0）

| 优先级 | 交付样张 | 建议数量 | 视觉要求 | 验收关注点 |
|---|---|---:|---|---|
| P0 | 月夜城堡/屋顶/庭院主场景概念 | 1 套，桌面与竖屏裁切各 1 | 暗黑电影感、半写实、藏青墨黑月白、少量朱红金 | 操作区背景亮度足够；桌面 11 人和手机可容纳 UI |
| P0 | 典型忍者塔罗牌正面 | 3 张：密探、变形者、盲眼刺客 | 统一修长比例、黑金纹边、清晰大编号、人物插画与精简技能文字 | 五阶段视觉扩展性、手机缩略可辨 |
| P0 | 统一忍者牌背面 | 1 张 | 黑金忍者徽章、暗纹、压印 | 所有未公开忍者牌背面完全一致 |
| P0 | 流派身份样张 | 3 张：鹤派/莲派/浪人 | 银白鹤纹/朱红莲纹/灰金孤月 | 未公开时不可被场景或席位无意泄漏 |
| P0 | 中立半身忍者肖像 | 3 名 | 服饰、面具、姿态有差别，不指向真实流派 | 11 人玩家缩略仍可读 |
| P0 | 关键机制静态帧/流程板 | 5 组：公开出牌、私密函、公开互换符印、刺杀反应、荣誉发放 | 每组“未触发/执行中/结算后”状态图 | 机制准确、无提前死亡/私有泄漏 |
| P0 | 11 人桌面/手机交互结构图 | 各 1 | 环形中央技能台、本人下中、底部手牌、手机当前目标优先 | 不遮挡计时、确认按钮、聊天入口 |

**P0 放行条件**：对电影感 × 塔罗风统一程度、缩略可读性、公开与私人投影做人工审查；未认可则只调整原型，不批量生产。

## B. 卡牌、流派和徽章（P1 正式素材）

| 资产类型 | 计划单位 | 数量建议与复用 | 需要保留的要素 |
|---|---|---|---|
| 四组通用忍者卡插画 | 密探、隐士、盲眼刺客、上忍 | 4 套不同的视觉母题；每组 6 张编号卡可**使用差异图案/排版变体**或细化到 24 张插画，视样张决议 | 同阶段编号 1～6 清晰、不用 24 张独立重绘作为硬门槛 |
| 六张骗徒卡插画 | 变形者、掘墓人、捣乱者、灵媒商人、窃贼、审判者 | **6 张独立插画** | 专属能力辨识、编号、效果精简 |
| 特殊卡插画 | 镜僧、殉道者、首脑 | **3 张独立插画** | 反应/揭示的合法使用窗口、不能误展示为普通阶段 |
| 统一卡牌背面 | 未公开全部忍者牌 | **1 套** | 完全一致，无法按背面识别具体牌 |
| 身份牌流派基底 | 鹤、莲、浪人 | 3 套 | 鉴别性家纹；展示按真实授权 |
| 身份牌级别排版 | 1～5 | **5 种数字/等级装饰模板**，与鹤/莲流派组合；浪人单独 | 数字越小等级越高；完整人数 4–11 的身份组合由规则表决定 |
| 牌面专属图标 | 五阶段＋六骗徒＋三特殊 | 最多 **14 个主题符号**（5+6+3） | 5 阶段均有辅助色、图标和文字；特殊牌不依赖颜色唯一辨认 |
| 家纹与荣誉徽章 | 鹤、莲、浪人、荣誉 | 3 个流派家纹＋荣誉正反 1 套 | 他人仅看荣誉背面/枚数；本人值 2、3、4 可见；数值可用文字层实现 |
| 卡牌详情与说明框 | 统一塔罗说明模板 | 1 套可伸缩 UI | 卡面简述、点选后完整说明，320px 手机不溢出 |

**数据不变量**：33 张忍者牌（密探6、隐士6、六骗徒6、盲眼刺客6、上忍6、特殊3），不允许 33 张卡背凭风格被分组识破。荣誉奖池 **35 枚=2 分14、3 分14、4 分7** 为数字版推定配置，实际 UI 的分值图案无需制作 35 张不同图。

## C. 人物席位及页面（P1/P2）

| 素材/UI | 建议制作量 | 细节 |
|---|---:|---|
| 中立忍者半身肖像库 | **至少 11 种可辨肖像** | 玩家自由选择、头像与真实流派无关；同肖像被多人选中时靠昵称/位置辨别 |
| 玩家席位框架 | 1 套响应式组件＋多状态变体 | 在线/离线、可选目标、当前发动者、已选择、确认等待、已死亡、荣誉枚数 |
| 桌面环形座位布局 | 1 套、覆盖 4/5/6/7/8/9/10/11 人 | 本人在下中；其他人相对排序，头像与手牌互不覆盖 |
| 手机紧凑座位区 | 1 套 | 320px 起可滚动；当前目标优先；关键按钮不遮挡 |
| 中央技能舞台 | 1 套 | 阶段名称、出牌、目标、反应、轮次、重要公开状态 |
| 底部手牌与轮抽窗口 | 各 1 套 | 手牌私有；轮抽第一/第二步及弃牌的选择明确 |
| 私人情报抽屉 | 1 套 | 历史时点快照及取得者权限，不能自动更新当前身份 |
| 公共事件时间线 | 1 套 | 按公开 eventId 排序；文字+关键静态关键帧；公共和私人严格隔离 |
| 聊天抽屉 | 尽可能复用平台已有公共聊天 UI | 不由《忍者之夜》重新造独立聊天系统，旁观不开放发送 |
| 观战视图 | 1 套同主题公共投影 | 无任何私有手牌、私人情报、玩家提交和公聊发送入口 |
| 轮末结算、比赛冠军面板 | 各 1 套 | 按真实事实计算，支持首脑/浪人、并列冠军和获奖者列表 |

## D. 技能动效：优先使用 CSS/矢量/程序化渲染（P2）

| 事件 | 实现建议 | 时长/约束 |
|---|---|---|
| 选牌/选目标/已提交 | 描边、底色、微形变与状态文字 | L1 100–200ms，不能外播秘密选择 |
| 当前执行对象 | 聚光/抬升/局部缩放 | L2 250–500ms，单一主焦点，多目标为同组 |
| 塔罗牌入场及翻面 | 2D/3D transform + 卡牌图片 | 默认出牌演出约 **0.8s** |
| 私人密函与封印 | 蒙层、可读文本与封印打开效果 | 仅当前合法获知者 |
| 变形者符印互换 | 两名目标之间的公开符印轨迹 | **实际交换才播放**；不显示两人的真实流派 |
| 刺杀攻击 | 局部暗场、刀光、短暂强对比 | 约 **1.8s**，不得在反应决议前提前播放死亡 |
| 镜僧反击/殉道者 | 反射光线 / 金属荣誉徽章升起 | 只播放对应服务端确认的反应结果 |
| 死亡状态 | 红光、去色、暗红框、死亡符号 | 明确区分“受攻击”和“已死亡”；**不震屏** |
| 荣誉授予/交换 | 徽章移动、数目更新、本人值展示 | 公开层只有背面和枚数 |
| 流派揭示 | 轮末存活者逐次翻牌/等级比较 | 总演出约 **3s**，动画顺序不改变同批次事实 |
| 冠军终幕 | 城堡月光、塔罗名牌、获胜者肖像与分数 | 约 **5s**，并列冠军同等突出 |
| 特效三档 | full/light/reduced 的参数化切换 | reduced 不放大/摇晃/闪烁，但保留顺序和必要文字 |
| 手机版演出 | 局部适配弹层/中心简化演出 | 反应计时、合法响应永远优先；不使用屏幕震动 |

**状态事件不是美术资产**：每次演出只能从服务端已公开事实或玩家私有授权事件驱动；要有 eventId、顺序、groupId、权限投影和回放文字。脱离服务端真相的假动画不得进入制作列表。

## E. 声音与未来公共音乐系统（P3 待启动，当前 0 个文件）

| 范畴 | 当前计划 | 本次是否制作 |
|---|---|---|
| 《忍者之夜》背景音乐 | 电影式弦乐/低频/环境，具体曲目由用户日后另设 | **否** |
| 《忍者之夜》技能音效 | 只定义各技能音频语义，实际音源待后续统一设计 | **否** |
| 公共音乐插件 | 类似已存在聊天公共能力，面向全部游戏提供注册、场景切换、资源管理与播放入口 | **否；独立任务** |
| 公共设置 | 音乐音量/音效音量分别调节，静音开关，用户偏好跨游戏复用 | **设计约定已冻结，尚未编写** |
| 音频入口建议 | 通过 gameId、scene、cue、eventId 和 visibility 向公共音频模块发语义事件 | **仅建议接口，不是项目现有 API** |

后续用户批准后另做“平台公共音频插件”方案与单独验收：先检查现有局部音效实现，再设计共享接口；首次开发不能破坏原两款游戏的音量、静音与游戏音效，也不得使三款游戏必须有音乐才能运行。

## F. 制作流程与质量验收

1. **P0 风格原型**：主场景、3 张忍者样卡、3 张身份卡、3 名中立肖像、5 组技能关键帧，以及桌面/手机布局概念。
2. **视觉原型评审通过后**，才批量制作牌面/肖像/家纹/UI；复用元素不影响实际牌型可读性。
3. **引擎/公私事件定义稳定后**，才制作动效与私密情报交互，不根据前端猜测生成事件。
4. 验收至少包含 4 人和 11 人布局、320px 手机、3 档动效、失联重连、旁观权限、变形者交换后提示、刺杀反应前后状态、荣誉值私密。
5. **旧游戏隔离**：所有本地测试使用独立端口/独立 SQLite，保护 3199 与当前两款游戏；美术工作不调用任何会修改真实对局结果的接口。
6. **权利与性能**：生成、绘制或外采资产需确认可使用、可发布许可；不要使用受限字体文件；图片与动效使用可优化的格式，控制下载大小和移动端内存峰值。
