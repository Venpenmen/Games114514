## 2. 绝不可破坏的游戏玩法基线

### 2.1 人数、身份与整场流程

- 4–11 人；偶数人数两派各 N/2，奇数人数鹤派与莲派各 (N−1)/2，额外 **浪人 1**。每派等级从 **1 到 5（数字越小等级越高）**，按人数依次加入对应级别。每轮重新发流派，变形者可改变本轮实际身份。
- 轮抽：每人最初 3 张忍者牌 → 秘密留 1、向左传 2 → 从收到的 2 张留 1、弃置 1；每人两张保留，33 张完整牌库仅发所需数量，未发出牌不混作弃牌。两步均为全体提交屏障；超时随机从**当前合法手牌**选择，不广播秘密选择。
- 每轮阶段：**密探 → 隐士 → 骗徒 → 盲眼刺客 → 上忍 → 流派揭示及首脑 → 荣誉派奖 → 冠军检查 → 下一轮或冠军**。各夜晚阶段先秘密提交是否出牌，提交完成或超时后**统一亮牌**，再按**同阶段卡牌印刷编号 1～6 递增结算**。该技能的目标、可选效果与反应使用独立子步骤；当前刺杀反应必须完整结束才能处理下一张牌。
- 仍存活的有效玩家可以执行普通出牌；已死亡玩家不能继续普通技能但可按已冻结规则继续公聊。未使用牌与全部剩余卡每轮结束回收，下一轮重新洗牌，不跨轮保留。
- 带完整轮次编号、跨轮荣誉所有权、已获情报与公开事件时间线。服务端重启/断线后恢复正确状态。

### 2.2 完整 33 张忍者牌

- **密探 Spy×6，1–6 号**：私看另一玩家当时流派；
- **隐士 Mystic×6，1–6 号**：私看另一玩家流派及其一张合法持有忍者牌（随机抽取，时点正确）；
- **骗徒 Trickster 六张，各一：** ①变形者 Shapeshifter：看两名玩家真实流派，可选交换且被交换者不能自行获知新身份；②掘墓人 Grave Digger：看两张真实弃牌、取一张，可即时合法使用或保留至合法时机；③捣乱者 Troublemaker：看目标流派，可公开其身份；④灵媒商人 Spirit Merchant：看目标流派或一枚荣誉，可与其交换各一枚且可交换未看过那枚；⑤窃贼 Thief：公开自己的流派，从荣誉**枚数**比自己多的玩家处窃取一枚；⑥审判者 Judge：公开自身流派并杀一人，**镜僧与殉道者不得响应**。
- **盲眼刺客 Blind Assassin×6，1–6 号**：刺杀合法目标；
- **上忍 Shinobi×6，1–6 号**：看目标流派再可选是否刺杀；
- **特殊牌各一：** 镜僧 Mirror Monk：应对盲刺/上忍，反杀攻击者、被袭者免死；殉道者 Martyr：应对盲刺/上忍，先获得一枚荣誉但仍死亡；首脑 Mastermind：持有者活到揭示阶段则所属派自动胜；持有者为存活浪人时两派均无法获得流派奖励，浪人仍获奖励。
- **这是真实的卡种/编号要求。** 之前聊天里的 AI 美术样张曾生成错误牌号和错误技能描述，绝不可照抄。卡牌原画与程序化的 `cardId / 阶段 / 编号 / 名称 / 规则摘要` 分离，程序严格从真实卡牌数据渲染；卡背完全统一。
- 掘墓人取得镜僧/殉道者/首脑不能无限制“立即触发”；这些牌只在**合法反应或揭示窗口**生效，必须跟踪其保留与使用状态；掘墓人强制选牌超时随机合法候选，其后是否立即发动超时默认保留；错过合法阶段不可本轮再强行使用。
- 强制合法目标超时：从当时合法集随机；可选效果超时：默认**不发动**；特殊攻击被回应者超时：**不回应**。原目标在执行时失效可按规则合法重选，无合法对象则失效；相同攻击最多一张反应牌。
- 特别测试：攻击者被镜僧反杀后原攻击目标存活，殉道者奖励即使本人死亡保留；审判者不能开启反应窗口；灵媒商人偷换真实 token 所有权；窃贼比较枚数不比较隐藏总分。

### 2.3 荣誉、流派胜负与比赛冠军

- **数字版已授权的荣誉初始有限池：35 枚 = 2 分×14、3 分×14、4 分×7**；这是依据实物 40 枚分值比例等比缩减的**数字版推定配置**，不是正式官方的 35 枚分布。无放回随机抽取；如果整批获奖者所需数量不足，**派发前**按同样 14/14/7 构成补池并记录事件，不能抽一半再补池造成分配不公平。
- 荣誉有单枚唯一 identity/owner/value；玩家本人可查看自身 token 数值与个人累计分数；其他玩家和旁观者只能看到**token 枚数**，不可看到面值及总分。交易后面值不变化。
- 轮末比较两派**存活成员的身份等级有序列表（1 最高）**，依次比较决定胜派；完全相同则两派均不胜，向所有存活玩家派奖；胜派**所有成员，包括本轮已死成员**各获一枚；存活浪人按规则额外获一枚；首脑合法触发覆盖常规派别比较。全部死亡时无胜派和生存奖励，但本轮已通过技能获得的荣誉保留。
- 先完成全轮荣誉派发，再检查是否有人累计分数达到 **10 分**；达标者中最高分胜，多人同最高分共同冠军，不加赛；夜间偷窃/交换提前达 10 不立即结束游戏。

## 3. 数字版房间、计时、身份安全与旁观

- 房主选定**固定人数 4～11**，只有达到该人数、所有正式玩家在线且已准备才开局；不能只满足人数上下限就开始。开局后不允许新的正式玩家顶替空席，允许独立旁观者（**不占玩家位、不能公聊、不能行动、仅看公开投影**）。
- 允许房主开局前配置：轮抽 `30/45/60/90s`（默认45），阶段出牌/统一亮牌 `20/30/45/60s`（默认30），目标选择 `15/30/45/60s`（默认30），刺杀反应 `10/15/20/30s`（默认15）；轮间准备固定30s。游戏开始锁定房间设置。不同子步骤计时由服务端真实截止时间决定。
- 相关玩家全部提交可提前过屏障；轮间所有正式玩家准备可提前进入下一轮，否则30s超时自动准备。离线被视为保留席位，由服务端按超时策略执行。
- 房主主动退出、掉线达到 **120s** 时，若有在线正式玩家则移交管理权；否则待有人重连再决定；房主权与秘密流派无关。已经开局的普通主动离开不允许移除席位，按离线处理。
- 所有**正式**玩家离线则游戏计时和自动托管暂停，重新上线恢复原剩余时间；只有旁观者在线也视为全员正式玩家离线。**活跃/暂停中的房间不得遭原平台24小时空闲清理**。服务器重启后也不得因旧 deadline 直接连跳一夜。
- 采用 Socket.IO 认证、服务端合法动作验证、单调递增操作/阶段 token、命令幂等 receipt、防重复派奖/刺杀、严格公私投影。历史情报以“取得时刻的快照”保存，秘密交换后的流派不自动更新。历史已公开流派是**当时真相**，不是永远有效的当前身份。
- 变形者的**用户特殊美术决定**：交换真实发生后，公共事件可显示“哪两名玩家之间发生符印互换”，但**不显示交换双方的新旧流派**。若仅发动而未交换则不得伪造已经交换；受影响两名玩家仅收到“你的流派卡可能发生变化”，不得自动更新真实流派视图。
- 旁观者只能读公共出牌、合法公开历史、存活状态、token枚数，游戏结束后可看正式终局结果；旁观者账号不能借客户端修改参数读取他人 private 资料、发送聊天或提交技能动作。
- 客户端重连恢复真实当前状态、本人可查看的荣誉、仍授权的私人情报历史、公开事件；不伪造过去的动画，不重新授予任何新信息。

## 4. 公共平台适配（必须向后兼容）

现有公共 SDK `GamePlugin` 支持 `minPlayers/maxPlayers/defaults/config/canStart/start/command/advance/public/private/finished/canChat`；现有服务器 SQLite 序列化 room、通过 Socket.IO 广播成员的各自快照，已有 command receipt。**利用原抽象，不要重写两个旧游戏。**

- **固定人数/开局**：游戏特有 `playerCount` config，加入和准备都准确检查；旧三人游戏沿用原条件。兼容旧 Room JSON、协议版本与配置。
- **多子阶段推进**：原公共 `advance` 在 deadline 到期时要求 `phase` 发生变化。新游戏有“秘密提交→同步亮牌→逐牌决议→私人目标→反应→回到牌序”，需要清晰可靠的递增全局版本或 step token，改变检查机制时保证旧游戏行为不变。测试同一阶段多事件、deadline 并发、旧消息到达、服务重启。
- **断线冻结与清理**：公共 `tick` 当前按服务器时钟推进；旧行为超过24小时空闲可能删除 room。仅对 Game 03 正式活跃/暂停的房间按能力标记冻结，明确恢复后时钟推算；其他游戏不改变原清理策略。
- **围观**：公共服务原快照只遍历 `room.members`；增加独立只读订阅及服务端投影，最小权限；围观不得计入玩家人数，不可见私人 `match.private` 与隐藏分值、不能公聊。
- **主持权**：增加可选的房主失联计时转移；此规则适配本游戏，旧游戏的 host/leave 行为不能意外变化。
- **轮次与整场**：`GamePlugin.finished` 只在冠军真正产生时返回 true；各轮末的30s准备由 Game 03 引擎内部处理，不回到公共 `ready/start` 页面。
- **聊天**：保留平台公共聊天室、限速/限长和 Socket 权限；Game 03 的公聊时机按已冻结规则，死人可以公聊，旁观者不可发言；公共记录与私有情报列表独立。
- **资源和可重启性**：Game 03 持久化可序列化状态不依赖 Vue 组件或运行中的动画句柄；重启时还原事件序列和当前权限，不能丢失已发荣誉、重复随机发牌。
- 安全：单人多个标签/重连、伪造 matchId/phase、越权查看、篡改用户身份、跨房状态请求均须服务端拒绝。重要数据不写前端全量 store、日志、HTML 数据属性或公开 WebSocket payload。

### 5.1 最终审美标准

- **环境**：原创暗黑电影感 × 半写实插画；月夜日式城堡、瓦顶、庭院、轻雾、灯笼、月光。藏青、墨黑、月白主色，朱红、暗金点缀；紧张神秘但不压抑，保留可玩的桌游聚会气质。
- **牌面**：修长的**塔罗式忍者卡牌**，精细装饰、神秘符号、清楚的阶段符号与编号；所有忍者卡统一**黑金忍者纹章背面**和不可推断的通用卡背。五阶段各配辅助色+符号+中文名称（不单靠颜色辨认）；牌名用有和风气质的中文宋体，操作文案、技能说明与规则用可读黑体。主卡仅显示短效果，点击/选中展开完整规则说明。
- **流派牌**：鹤派银白鹤纹、莲派朱红莲纹、浪人灰金孤月；等级 1–5 以大数字+身份称谓+等级装饰表达，明确 **1 最高**。所有未经公开的身份牌只在本人有权限的视图出现。
- **荣誉徽章**：古铜/暗金金属家纹质感；所有人看到背面和**数量**，拥有者才看到自己的 2/3/4 面值。交换荣誉时也保持保密。
- **席位人物**：至少 **11 名风格统一、彼此可辨的中立忍者半身肖像**，服装、面具、姿势各异，玩家可选；肖像绝不关联流派、等级或技能，不能让其他人通过图像推测秘密身份。死亡转为去色、暗红边框和死亡标识，仍显示昵称及荣誉枚数。
- **桌面布局**：真正的**环形对局式**，本人永远位于底部正中，其他 3–10 人按相对座次环绕中心行动舞台；8/11人仍能读出昵称、在线与生死状态、荣誉枚数。本人底部手牌栏固定，轮抽时私有手牌在中央放大。左/右区域分别承担公共事件、聊天、私人信息抽屉，但不要让多个弹窗遮挡焦点。
- **手机布局**：320px 起适配；当前合法目标/动作/计时优先；其他玩家紧凑可滚动，聊天、公开时间线、私人情报各有入口。触屏合法目标高亮后**二次确认**，不能直接点一下就提交危险操作。
- **视觉质量**：与本游戏前期批准的月下城堡/塔罗牌/三派流派/桌面环形/手机刺杀概念保持**主题一致**，但那些概念图仅代表风格样张；其中文字、卡牌号、技能内容曾有错误，**不能用作数据或整页成品截图**。正式游戏需真实分层 UI，所有操作与头像可按人数动态变更，不可将截图作为不可点击的背景。

### 5.2 从生成到正式交付的素材工程流程

1. 优先使用 Codex 执行环境实际可用的**受许可图像生成能力**产出原创图片；核查是否可以调用图像生成模型、项目本地工具、已许可外部资源或合法图像管线，确认调用方式、费用与许可。不能假设存在图像 API 或擅自付费。用户此前批准的 ChatGPT 概念图若不在当前工作树，就只以文档的风格描述为基准，**不得虚构本地路径或要求直接从对话里的截图抽取透明素材**。
2. 先制作少量**真实原画样张**：月夜城堡背景（适合 16:9 + 9:16 裁切）、密探/变形者/盲眼刺客三种塔罗牌主体、统一背面、鹤莲浪身份卡、三名中立忍者、荣誉徽章；立即以实际 Vue 界面做桌面/移动两种嵌入预览，检查文字/裁切/亮度/主题统一性。通过自动检查后继续批量制作，不每一步停下来索要用户许可。
3. 批量输出六种骗徒独立主题、四类普通忍者牌主题（允许同类别编号卡复用插画模板但视觉必须达到一致的正式质量）、镜僧/殉道者/首脑独立原画、共至少11名可选择中立肖像、三派图案、牌背、家纹、荣誉徽章与背景。要覆盖**33 张卡牌对应的实际数据定义**；图像数量不必强行33张独立绘图，但每个卡种有清晰且适当的正式视觉表现。
4. 正面图**只存画作与装饰性底层**，牌号、技能中文、身份和数值由 Vue/组件用真实数据叠加：生成图中的错别字、伪数字或幻觉规则一律不能进入正式牌面。若图像工具只能生成带错文字的完整图，要裁切/覆盖或重新生成纯插画主体和无字卡框。
5. 图像进行裁切、透明通道处理、分辨率与尺寸规范化、压缩为 WebP/AVIF 或适用格式；使用规范、可预测资源命名以及版权/来源/生成方法登记，不提交生成过程临时大图、未优化原始文件或受限字体。
6. 静态动效可用 **CSS transforms/opacity、SVG 和程序化光效**，不要为一个小亮光逐帧生成巨幅位图；复杂刀光/镜光/符印可拆成透明层、CSS 轨迹和短时序组合。不要将全部效果压成一张静态截图。
7. **若 Codex 环境没有可合法调用的半写实插画生成能力**：必须在 `ASSET_STATUS.md` 中列出真实能力、可生成/不可生成项，先以清晰标记的低成本占位图完成引擎与 UI；绝不能将 CSS 抽象图形/低质占位冒称达到了已认可的原创半写实插画标准。优先完成可自主完成的程序化 UI 和动效，不要因素材生成暂时受限而停止规则引擎与测试。尽量找到合法、无需额外付费的可用方案，但不得绕过授权、购买或盗图。

### 5.3 技能动画完整清单（必须遵守已冻结的语义）

- **L1 100–200ms**：选牌、选目标（只有本人可见）、确认提交、已提交等待；必须明确区别“选中”和“已提交”。
- **L2 250–500ms**：当前执行者头像聚光、当前目标发光轮廓/脉冲，单主焦点；同阶段先**统一公开实际打出的牌**再按编号顺序执行，不能提前亮出他人已提交的牌。
- **公开出牌约0.8s**：塔罗牌飞入中央、翻转、放大、显示发动者和技能名；后续进入真实合法目标操作和结算。
- **密探/隐士**：给授权者展示私密密函展开、封印解除、信息快照，其他人只见合法公开动作；历史快照按轮次+时间查询。
- **变形者**：**只有真正确认并执行交换**，全体看到两个目标席位之间的符印互换动画；严格不显示前后流派。两名被交换者只收到模糊通知；未交换不能冒称交换成功。
- **攻击约1.8s**：局部快速暗场、刀光掠过目标、短冲击；**攻击发生≠目标死亡**。被攻击者先获得合法的限时反应提示；镜僧镜光反弹并反杀、殉道者暗金荣誉符印后死亡，审判者不可响应。最后再确认实际生死。
- **死亡**：短红光暗影、头像去色、边框暗红、死亡文字与图标。失败刺杀、上忍放弃不能播放死亡。
- **荣誉**：金属家纹徽章自池飞向得主；得主自己看到真实面值，其他人只看到统一背面及枚数变化；补池显示公开文本，补池数量/面值分布不能误泄漏当前余池秘密。
- **轮末揭示约3s**：存活玩家身份可按展示顺序翻开，但服务器同一结算事实不变；中央真实比较等级、有首脑/浪人时正确显示特殊原因；获胜派和颁奖透明准确。
- **冠军约5s**：月光照亮城郭，冠军人物肖像与塔罗式名牌，个人荣誉与比赛最终结果；多名同分冠军并列展示，不能只选一人。
- **全员统一观演出**：普通正常客户端按服务端结算事件时间戳/顺序共同观看完整 L4 事件，不提供一人快进改变房间阶段的能力；**服务端裁决及合法响应不等待所有客户端动画 ACK**，断线设备或减少动态的玩家不构成死锁。限时反应按钮/倒计时优先；不能为了 1.8s 刺杀动画而让受击者损失反应时间。
- **不得屏幕震动**，只用局部缩放、卡牌与光效；动画设完整/轻量/减少动态三档，遵守 `prefers-reduced-motion`。低性能手机自动轻量；减动画模式也要保留同等事实、顺序和文本。
- **事件可靠**：所有演出由服务端真实公开/私人事件驱动，建议 `eventId/matchId/phase/sequence/kind/targets/groupId/visibility/recipients/resultText`；超时多事件可续播/快进至最新，重连不重放不存在的实时事件。公共事件时间线含文字及合法静态关键帧，和私人情报完全隔离。

### 5.4 音频系统这次的严格范围

- 用户明确：**目前整个项目未完成统一背景音乐系统**，未来要像公共聊天能力一样开发为**所有游戏共用的音乐/音效插件**；曲目和音乐制作将在另一轮单独决定。
- 本次不生成、购买、下载或选择背景音乐；不必现在完成全平台音频播放器，更不能强迫其他两款游戏迁移；但要为本游戏**预留清晰、可选、无依赖的语义事件入口**，例如 `musicCue/scene/sfxCue`。
- 后续公共模块须支持 `musicVolume`、`sfxVolume`、`muted` 分控与一键静音，并考虑浏览器自动播放限制、独立 gameId、事件去重、用户偏好。现有局部音效保持可用，本次不要破坏。
- `ART_DIRECTION.md` 中提议的 `audio.enterScene/emitCue/setPreferences/leaveScene` 是**设计建议，不是现有 API**，不要在不存在的公共播放器上强行调用而造成运行错误。本次可准备类型/轻量空适配接口并写明后续接线点。
