# 《忍者之夜》美术与交互设计规范 v1.0（五轮冻结稿）

> Games114514 / Game 03，2026-11-16。状态：**五轮美术问卷全部冻结**；属于设计交付，**并不代表素材、界面、音效或插件已实现**。
> 上位规范：[`../../MECHANICS_VISUAL_FEEDBACK.md`](../../MECHANICS_VISUAL_FEEDBACK.md)《机制反馈与结算演出规范 v1.0》；规则依据：[`RULES.md`](RULES.md)、[`IMPLEMENTATION_REVIEW.md`](IMPLEMENTATION_REVIEW.md)。如设计与规则隐私或服务器时间冲突，以规则、服务端授权和平台规范为准；不得默默改变用户五轮选择。
> 美术风格独立于《诡吹灯》《骰子狼人杀》；仅复用统一机制反馈语义、公共 UI/权限/聊天、以及以后公共音频服务的接口。

## 1. 五轮冻结决策总表

### 第一轮：世界观、气氛与视觉（7 项）

1. 整体美术：**暗黑电影感与半写实插画**，不是水墨风或原版仿制风。
2. 气氛：**神秘、紧张，但不压抑；适当保留娱乐性**。
3. 色彩：**藏青、墨黑、月白为主；朱红与金色点缀**。
4. 环境：**月夜日式城堡、屋顶与庭院**。
5. 原版关系：**保留玩法及经典忍者元素，重新设计独立美术**，不直接使用原版牌面图。
6. 细节密度：**场景与人物精致，操作区域克制清晰**。
7. 整体动效：**常态轻微动态，关键技能有明显演出**。无其他附加要求。

### 第二轮：桌面和移动端交互（9 项）

1. 桌面：**环形对局式**，所有玩家围绕中央行动区；不是中心舞台上下分列。
2. 自身座位：**画面下方正中固定**，其他玩家按相对座位顺序排列；4–11 人自适应，不能用动画挤压自己的席位。
3. 玩家席位：**半身人物头像 + 昵称 + 生死状态 + 荣誉标记枚数**；头像不可暗示实际秘密流派。
4. 手机竖屏：**当前目标优先**；其他玩家在可滚动的紧凑席位区，320px 起保证可点击。
5. 本人手牌：**底部固定手牌栏**；轮抽时手牌放大至中央操作区，放大不等于公开。
6. 私人信息：**私人情报抽屉**，按轮次、阶段、取得时刻记历史快照；不自动更新变形后的身份。
7. 选目标：**点选席位高亮 → 明确二次确认**；先判断合法目标，未确认的秘密选择不可对外展示。
8. 社交：**聊天抽屉与公共事件时间线分开**；死人可按规则公聊，旁观者不可聊天。
9. 旁观：**相近的公开场景，但不提供手牌、私人信息、正式玩家行动入口**，后台也不发私有投影。无其他附加要求。

### 第三轮：卡牌、流派与人物（10 项）

1. 忍者牌：**塔罗式竖长卡**，修长构图、精细装饰、神秘符号；人物/背景继续服务于半写实电影感。
2. 牌背：**统一黑金忍者纹章**，暗纹与金属压印；未公开牌背不能据类别区分真实牌型。
3. 五阶段：**各自辅助色 + 专属图标 + 中文文字名称**，颜色并非唯一识别方式。
4. 流派：**鹤派银白鹤纹、莲派朱红莲纹、浪人灰金孤月**；仅当授权获知或确实公开时展示身份。
5. 身份等级：**显眼的 1–5 等级数字 + 身份称谓 + 等级装饰**；明确数字越小等级越高。
6. 席位角色：**玩家自选中立忍者外观**；外观与真实流派、技能、等级绝无关联。
7. 肖像：**半身人物**，服饰、面具和姿势各异；为 11 人密集布局设计裁切和短昵称。
8. 死亡：**肖像去色、暗红边框、明确死亡标识**，仍显示昵称与荣誉枚数；死亡不自动泄露流派。
9. 荣誉：**古铜/暗金家纹金属徽章**；仅拥有者可看见面值，其他人看到背面与枚数。
10. 技能文案：**卡牌显示简短效果，选中后展开完整技能说明**。无其他附加要求。

### 第四轮：技能演出和重大结算（11 项）

1. 出牌：**发动者席位聚光 → 塔罗牌飞入中央 → 翻转放大并展示技能名称**。
2. 目标：**目标席位醒目的发光轮廓/脉冲**，结算时局部放大；**私选与公开结算有不同状态**。
3. 情报：**私人密函展开、封印解除**，仅查看者得到真正情报；旁人只看公开出牌事件。
4. 变形者：**发生实际流派交换后，对所有人公开展示两名目标之间的符印互换，不展示交换前后身份**。这是用户特意选择的**数字版公开性约定**；如果最终没有交换，不得伪造“已经交换”的公共动画。
5. 刺杀：**中央快速暗场 → 刀光掠过目标 → 短暂冲击 → 公布真实生死**，不提前宣告死亡；待反应未决时只能提示“遭受攻击”。
6. 镜僧：**镜光反弹刀锋**；殉道者：**暗金荣誉符印升起，随后死亡**。攻击反应先于这次攻击最终死亡判定；审判者无这两种反应。
7. 死亡：**短暂红光与暗影冲击 → 逐渐去色 → 暗红边框和死亡标识**。
8. 荣誉：**金属徽章自奖池飞向获奖者**；本人展示真实分值，其他人仅背面及枚数；交换荣誉也不能给第三方显露面值。
9. 轮末：**存活者依次公开翻流派卡 → 中央比较双方存活等级 → 突出胜利流派**；首脑和浪人按规则单独表达，按服务器结算记录排序；不得把“演出依次翻牌”误认为身份在逻辑上顺次改变。
10. 全场冠军：**月光照亮城堡、冠军肖像与塔罗式名牌居中，个人荣誉与最终总分展示**，支持多人并列冠军。
11. **所有在线正式玩家统一观看完整重大演出，再展示下一步骤**（用户选项，不是“个人跳过”）。但这不能阻塞服务器合法响应时限、等待掉线者确认，亦不能更改结算、强制忽略减少动态功能。无其他第四轮要求，另要求严格符合平台公共机制反馈规范。

### 第五轮：排版、音频、节奏、移动与历史（9 项）

1. 字体：**标题/牌名为和风气质宋体；操作与规则正文为清楚易读黑体**。统一字符度量，数字和操作状态可单独强调。
2. 音乐方向：**电影配乐式弦乐、低频冲击、环境音**；这只是创作方向，暂**不引入背景音乐/音频素材**，未来用户另设音乐。
3. 设置：**背景音乐与技能音效分开调节音量，提供一键静音**，并保留设备静音行为。
4. 时间：**出牌约 0.8s、刺杀约 1.8s、流派揭示约 3s、冠军约 5s**；参考基于 L1–L4，不构成服务器回合计时。
5. 同步：**服务器先裁决，客户端同步呈现；可存在统一展示窗口；限时反应/合法操作不被动画遮挡**，不得等待全部客户端 ACK 后才推进。
6. 镜头：**完全不使用屏幕震动**，仅卡牌、局部缩放、光效表达冲击；不是“微量震动”。
7. 性能：**完整 / 轻量 / 减少动态**三档可手动设定，自动为低性能设备提供轻量特效；跟随系统 reduced-motion。
8. 手机：**中央紧凑演出 + 背景席位适度暗化**，限时反应的按钮与剩余时间始终拥有最高优先级。
9. 回看：**公开事件时间线保留文字与关键静态画面；私人历史情报另行保存**，重连不得伪造历史动画。
10. 用户补充：音乐当前尚不完整，**未来音乐系统做成类似聊天系统的公共插件/服务**，所有旧/新游戏都可复用；此轮仅保留接口，不开发、不生成音乐。

## 2. 基础视觉语法与响应式结构

### 2.1 场景与颜色（设计方向；精确 token 值开发时再由视觉原型验收）

- 场景层：深藏青夜空、墨黑城郭、明暗月光、局部薄雾与庭院廊檐；不能让复杂背景压低前景信息可读性。
- 对局层：暗色半透明桌面纹理与温和金属框线，中央行动台与四周座位清楚分离。
- 主题色职责：月白负责正文/中立信息；金色用于荣誉和重要确认；朱红用于危险和死亡；行动阶段另用五套专属辅助色与图标；**不能把“选中、已提交、危险、已死亡”只用红色表达**。
- 人物造型：独立中立忍者半身肖像，统一裁切基准；不露出与秘密身份对应的流派标记。
- 卡牌：竖长塔罗卡、黑金牌背、稳定标题栏与编号区、绘画主体、精简规则区、技能图标；牌面完整版说明放交互详情。
- 字体：中文宋体标题与牌名、黑体说明；确保合法使用/系统回退字体，不内嵌未经许可字体文件。暗色底下维护足够文字对比度。

### 2.2 桌面 4–11 人环形布局

- 以本人下方正中作为 6 点方向的参照，其他玩家按绝对座位号映射到相对环形位置；包括 11 人时的其余 10 人，避免姓名叠压。
- 中央行动区固定承载阶段名、当前技能牌、公开执行对象、攻击/反应反馈、轮末揭示；不把 11 张人物大肖像同时挤入中央。
- 底部玩家席位与底部手牌栏同屏存在：座位靠上，手牌靠下，二者不互挡；轮抽时中央覆盖本人私有轮抽面板。
- 玩家席位标明昵称、联网状态、死亡/生存、荣誉**枚数**；身份展示必须以公开或私人授权为准。
- 选中目标（L1）→ 确认提交（独立图标/文案）→ 已提交等候（L1）→ 服务端公开执行（L2）→ 结果（L3）→ 冠军（L4）必须能一眼区分。

### 2.3 手机竖屏与旁观

- 手机 320px 起以中央“当前合法行动/当前受影响目标”优先；玩家在紧凑可滚动席位区，当前本人及被选中目标始终可定位。
- 底部固定手牌，但不得覆盖系统安全区、聊天开关、限时反应与倒计时；虚拟键盘出现后保持关键按钮可操作。
- 私人情报、聊天、公开事件历史为三个独立功能，不合并保密和公共事件。
- 旁观者使用同类环境视觉及公开席位/事件，不提供任何手牌、选目标、私人调查或聊天入口；服务器只发公开投影。

## 3. 平台 L1–L4 反馈与安全时序映射

| 级别 | 《忍者之夜》事件 | 视觉机制 | 应遵守的规则 |
|---|---|---|---|
| L1 选择/提交 | 选卡、轮抽、选目标、已确认 | 100–200ms 高亮/描边、状态文字、局部变形 | 未公开选择绝不外播；已提交不可误显示为已结算 |
| L2 执行焦点 | 公开出牌、当前编号结算、多人目标高亮 | 局部聚光 250–500ms，塔罗牌放大，明确发动者与当前目标 | 按阶段先统一亮牌，后按牌号顺序；不提前公开秘密目标 |
| L3 结算结果 | 攻击反应、死亡、公开身份、荣誉增减 | 动画+文字+明确结果；刺杀段约 1.8s | **先反应后判断死亡**；一组同时受影响对象按 groupId 同组表达 |
| L4 重大节点 | 轮末揭示、派奖、比赛冠军 | 汇总面板、完整摘要、可查记录；揭示约 3s、冠军约 5s | 轮末全体奖项发完才检查 10 分；不遮挡必须即时响应的操作 |

### 3.1 所有人统一观看：严格的实现定义

- 服务端先生成**真实已授权的结算事件**，带唯一 `eventId/matchId/phase/sequence/visibility/recipients/groupId/resultText` 等字段，并决定统一可见演出开始时点及下一正常步骤的可见窗口。
- 在线客户端依同一逻辑顺序播放完整默认演出；不能一人点“跳过”而令服务器跳过别人的过程。**不得等待所有客户端动画完成上报才裁决或开窗**：掉线、刷新、慢手机不构成推进死锁。
- 在服务端业务截止与展示窗口冲突时，**以合法提交窗口优先**：反应倒计时照真实规则运行，前端为收到反应资格的玩家立即显露可操作按钮。可将攻击的“最终斩杀”视觉移至反应判定完成后，不得一面播放死亡一面尚待镜僧/殉道者响应。
- “所有玩家完整观看”是正常在线、正常动态设置下的统一展示节奏。系统/手动减少动态者应看到**相同阶段、同样结果、等价文字与静态关键帧**，可以没有闪烁和连续放大。恢复中途的玩家直接重建最新真实阶段及可查历史，不为补片阻塞。
- 不使用震动或晃屏。所有长演出有可读文字摘要、键盘可操作的焦点恢复、可重复查阅的事件记录。

### 3.2 需要严守的公开/私人边界

| 事件 | 公共画面 | 有权限的私有画面 |
|---|---|---|
| 密探/隐士 | 发牌人/被执行的公开牌及合法公开状态，不显示查到的流派/手牌 | 密函显示查看时快照，记录轮次时间 |
| 变形者 | **只有实际执行交换**，显示被交换两人的公开互换符印及事件文本，不出现身份图案/数值 | 变形者查看的身份信息；受影响两人仅收到“可能变化”的私人提示，不自动刷新身份 |
| 盲眼刺客/上忍刺杀 | 发动者/合法公开的目标、被攻击状态、反应后实际生死 | 仅被刺杀者收到合法反应提示；未公开的持牌信息不外泄 |
| 镜僧/殉道者 | 仅在真的发动后公布反应卡、反击/获荣誉/死亡结果 | 可回应者在计时内看到反应选择 |
| 荣誉发放/交换 | 收到/移出的徽章背面、数量增减 | 获得者可见其真实面值；未持有者不可见 |
| 轮末身份与首脑 | 按真实揭示事实和规则展示身份及输赢，历史上已公开的旧情报保留其时点 | 未公开或过期的私人认知不自动升级为当前真实身份 |
| 旁观者 | 仅公开事件时间线和公开席位 | 不存在私有投影 |

## 4. 音频：当前冻结需求及未来公共插件边界

**现状**：当前平台已有零星游戏音效，没有统一背景音乐系统。第五轮确认**本次仅保留接口约定，不引入任何背景音乐文件、音乐播放器实现或音频资源**。

- 《忍者之夜》音乐方向：电影式弦乐、低频冲击、环境音。具体曲目、片长、循环、段落、来源与版权许可均**留待用户后续另行设置**；不可擅自自动选歌或制作音乐。
- 统一系统未来应作为**跨游戏公共音频模块/插件**：公共层提供音频策略与设置接口，游戏插件只输出语义化 `musicCue/sfxCue/scene` 等事件，不直接控制全局音量或播放别的游戏素材。
- 公共用户设置：`musicVolume`、`sfxVolume`、`muted`；音乐和效果音独立，用户一键静音，遵守浏览器播放权限和 reduced-motion 相关偏好；未来 Android/Windows 容器保持一致语义。
- 建议插槽（**建议契约，不是既存接口**）：`audio.enterScene(gameId,scene)`、`audio.emitCue(gameId,cue,eventId,visibility)`、`audio.setPreferences(prefs)`、`audio.leaveScene(gameId)`。播放器层处理重复事件去重、场景切换、音量以及多游戏隔离。
- 可预留的忍者音频语义：`night-enter`、`card-reveal`、`secret-intel`（private）、`attack`、`counter`、`honor-awarded`、`faction-reveal`、`champion`，**这些名称仅作未来实施提议**，目前不制造播放承诺。
- 后续应独立建立公共音乐系统需求/设计/测试任务，覆盖《诡吹灯》《骰子狼人杀》《忍者之夜》；用户另行决定背景音乐后再推进，不能使本游戏功能引擎依赖“音乐已完成”。

## 5. 验收标准与下一步

1. 无论动画设置，任一玩家都能说出当前阶段、当前作用对象、已提交还是已结算、公开结果；按完整/轻量/减少动态三档检查一致。
2. 11 人桌面/320px 手机，昵称与关键状态可读，合法目标容易点击且需确认；私有抽屉不与聊天/事件混线。
3. 所有公开演出来源于服务端真实公开事件，具有顺序/去重/回放信息；身份、私人情报、荣誉面值不经公开快照泄露。
4. 攻击反应优先于最终死亡演出；同时目标分组展示；变形者仅在实际交换后公布两名交换目标且不泄露流派。
5. 全员统一展示不能等待离线设备、阻断反应或改变服务器截止时间。浏览器刷新/重连只呈现最新真实状态及授权历史。
6. 正式音频资源与播放逻辑**不在本轮交付**；公共音频插件作为跨游戏后续项目。
7. 先做小规模场景和塔罗式卡牌视觉原型评审，再批量制作素材；不直接将参考图当作最终可发布资产。
