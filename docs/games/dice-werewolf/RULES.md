# GAME 02《骰子狼人杀》冻结规则

## 4.1 玩家和比赛

- 固定三名玩家。
- 一场完整比赛包含多局游戏。
- 房主可选择目标积分 3、5、7 分。
- 默认目标积分为 5 分。
- 每局结束，获胜玩家各获得 1 分。
- 失败玩家不得分。
- 一局可以产生多名获胜玩家，也可以无人获胜。
- 不保存跨比赛的长期竞技积分；本场比赛内正常保存与恢复积分。
- 每次开始全新比赛时，玩家可以重新选择赌徒形象。
- 同一场比赛内的普通局与加赛局保持已选形象。

## 4.2 随机身份

每局开始时，服务器为三人分配 1～6 的隐藏骰子点数。

**普通比赛阶段：**

- 每名玩家随机获得一个点数。
- 允许两名玩家点数相同。
- 如果三人点数完全相同，重新随机分配。
- 身份只向对应玩家展示。
- 其他玩家不得提前获得身份信息。

**加赛阶段：**

- 三人的身份点数必须互不相同。
- 每一局重新随机分配。
- 玩家无法自行指定点数。
- 身份依然保密。

随机分配应公平，不得通过固定顺序或固定组合偏向特定玩家。

## 4.3 六个点数与生命值

游戏具有 1～6 六个公共点数。

- 每个点数独立拥有一条公共生命值。
- 初始生命值均为 0。
- 所有玩家都能查看六个点数的生命值。
- 多名玩家如果拥有相同身份，则共享该点数生命值及其相关胜负。
- 某个点数被处决后永久移出本局。
- 已移出的点数不能再成为操作或投票目标。
- 一局重新开始时，六个点数及生命值重置。

## 4.4 行动阶段

每轮按照仍然存在的点数从小到大依次报数。

每个点数行动持续最多 30 秒。

全部三名玩家都需要秘密选择：

- `+1`：当前点数生命值增加 1。
- `-1`：当前点数生命值减少 1。

没有有限手牌，也不设置行动消耗。

所有玩家提交完成后立即结算，无需等待倒计时结束。

若玩家超时，服务端对该玩家等概率随机执行 `+1` 或 `-1`。

提交后不可修改。

结算后公开：

- 当前点数
- 本次生命值变化
- 结算后的生命值

**不得公开具体哪个玩家选择了 +1 或 -1。**

不要通过日志、客户端私有状态或额外接口泄漏个人操作。

## 4.5 生命值处决

全部现存点数完成一轮报数后，执行生命值检查。

所有生命值小于等于 -5 的点数，同时被处决。

注意：

- 点数在当前操作结束后达到 -5，不代表立即移除。
- 必须等到这一整轮报数全部完成。
- 同一轮可能同时处决多个点数。
- 多个处决必须作为同一次原子结算处理。
- 不得因为先处理某个点数就漏掉同轮应处决的其他点数。

生命值处决完成后立即检查普通终局。

如果命中玩家身份，则本局结束，不再进行后续投票。

## 4.6 投票处决

如果生命值处决未结束本局，检查特殊终局；若仍未结束，进入投票。

每名玩家选择一个尚未移除的点数。

- 投票时间 30 秒。
- 提交后不可修改。
- 三人全部提交时立即结算。
- 超时由服务器从现存点数中等概率随机选择一个目标。
- 至少两票投向相同点数，该点数被处决。
- 未形成两票一致，则重新投票一次。
- 第二次投票仍未形成两票一致，跳过本轮投票处决。

投票期间不显示其他玩家的目标，只显示提交状态。

每次投票结束后必须公开：

- 每名玩家的投票对象
- 是否由服务器超时代投
- 票数统计
- 是否构成有效处决

两次投票都要分别公开结果。

投票处决完成后检查普通终局和特殊终局。

## 4.7 普通终局及积分分配

任何一次有效处决，只要命中一名或多名玩家持有的身份点数，本局立即结束。

- 身份被处决的玩家失败，获得 0 分。
- 身份未被处决的玩家获胜，各获得 1 分。
- 如果三名玩家的身份在同一次处决中全部命中，则全部失败，本局无人得分。

示例：

A=1、B=3、C=5，处决 3：

- A +1
- B +0
- C +1

A=2、B=2、C=5，处决 2：

- A +0
- B +0
- C +1

A=1、B=3、C=5，同时处决 1、3、5：

- A +0
- B +0
- C +0

同一次自动处决中的多个命中点数必须统一判定，不得提前按第一个命中点数发放积分。

## 4.8 两点数特殊终局

普通比赛中，如果一次处决结束后：

1. 没有命中任何玩家身份；
2. 场上恰好只剩两个点数；
3. 三名玩家身份为两人同点、一人不同点；

则立即结束本局：

- 两名重复身份玩家失败。
- 另一名玩家获胜，获得 1 分。

**判定优先级：普通处决命中玩家优先于两点数特殊终局。**

例如：

A=2、B=2、C=5，场上剩 2、4、5。

若处决空点数 4，剩下 2、5：

- A、B 失败；
- C +1。

若处决 5：

- 普通处决优先；
- C 失败；
- A、B 各 +1。

加赛阶段三名身份互不相同，因此不会触发重复身份特殊终局。

## 4.9 连续三轮无处决机制

在同一局内统计连续没有任何点数被处决的完整报数轮次。

每个完整轮次包括：

- 现存点数全部行动
- 生命值处决检查
- 投票与必要的重投
- 本轮结果结算

规则：

1. 如果本轮有任何点数被处决，计数清零。
2. 如果本轮没有任何点数被处决，计数 +1。
3. 连续三轮没有点数被处决，触发系统强制处决检查。
4. 如果存在尚未移除、且没有玩家身份对应的空点数，系统从中等概率随机选择一个进行处决。
5. 如果没有空点数，系统跳过强制处决。
6. 无论是否找到合法目标，本次检查结束后计数清零。
7. 系统随机处决后仍需检查特殊终局。
8. 新的一局计数重新从零开始。

**禁止系统为推进游戏而强制处决有人持有的点数。**

这意味着当所有空点数都已移除、玩家又长期无法达成有效投票时，单局理论上可能无限持续。

这是用户确认接受的规则，不得擅自添加最大轮数、强制扣血或随机杀死玩家的机制。

## 4.10 整场比赛与加赛

每局结束后，累计获胜玩家的积分。

普通阶段满足以下两个条件时，立即结束整场比赛：

- 最高积分达到目标分数；
- 最高分只有一名玩家持有。

如果最高积分已经达到目标，但最高分存在并列，则进入加赛。

进入加赛后：

- 三名玩家全部继续参赛。
- 所有积分保留。
- 后续每一局三名玩家身份必须互不相同。
- 始终保持加赛模式，不再返回普通阶段。
- 单局规则、处决规则和得分规则不变。
- 直到出现唯一最高积分玩家，宣布其为冠军。

例如目标 5 分：

- 5 / 4 / 3：比赛结束，A 冠军。
- 5 / 5 / 3：进入加赛。
- 6 / 6 / 3：继续加赛。
- 6 / 5 / 4：A 冠军。
- 5 / 5 / 6：C 冠军。

加赛可能持续多局，这也是用户接受的规则。不得自行设置强制终结局数。

## 4.11 游戏结束展示

单局结束必须公开：

- 所有玩家真实身份点数
- 处决方式和原因
- 被处决的点数
- 六个点数的最终生命值
- 每名玩家的本局胜负
- 本局获得积分
- 整场比赛累计积分
- 是否进入加赛或继续加赛

整场比赛结束时另外展示：

- 唯一冠军
- 最终三人积分
- 比赛结果

# 五、聊天、时间、超时和重连

## 5.1 时间参数

- 每个点数操作阶段：30 秒。
- 每轮投票：30 秒。
- 首轮投票失败后的重投：30 秒。

全部相关玩家提交完成时可提前结算。

投票结果建议展示约 3 秒，并提供本局记录查看入口。

## 5.2 公共聊天

整个单局允许公共文字聊天。

聊天不得暴露服务端保存的隐藏身份或秘密行动。

玩家可以通过聊天讨论、误导或交换信息，但服务器不为其推断或验证身份声明。

继续使用平台已有的聊天权限、安全过滤、历史和限流机制。

## 5.3 超时与掉线

- 掉线不暂停游戏。
- 超时行动由服务器随机选择 +1 或 -1。
- 超时投票由服务器随机选择一个现存点数。
- 自动提交应具有清晰提示。
- 断线玩家重新连接时，只恢复自己的私有信息及当前公共状态。
- 重复请求不得产生多次行动、处决或积分增加。

## 5.4 状态恢复

服务器重启后需要恢复：

- 当前单局
- 当前阶段及绝对截止时间
- 玩家身份和积分
- 六个点数及生命值
- 已提交操作
- 投票及重投状态
- 无处决计数
- 是否已经进入加赛
- 已完成结算的幂等标记

不能依赖单一浏览器倒计时或仅存于内存中的定时器。

## 实装约定

投票公开阶段为 3 秒。本局结束后自动续局前保留结算 8 秒，续局后可打开上一局完整记录。冠军结果保留至下一场比赛开始或房间关闭。每个成员的赌徒形象须在准备前选择，比赛开始后整场锁定。房主通过通用房间设置修改目标分数。

单局结算包含最后一次有效处决的原因、同批目标、身份与最终生命值；票型和此前处决可在本局记录查询。
