# P20.8 验收与回退

## 核心变更

- 正式席位直接读取 SQLite 的房间成员关系，创建和加入在写入前复核。既有暂离占席，正常移出、退出、解散和过期沿用原规则。若其他数据副本已有多房旧席位，保持原记录且拒绝新增席位，由原生命周期释放。
- 设备会话仍保护比赛投影，服务端同时指定唯一有操作权的 Socket.IO 连接。刷新可凭原标签页标识恢复。其他标签页收到脱敏快照，接管时比赛控制版本递增。浏览器导航脱离当前连接，不退出成员关系。
- 《忍者之夜》桌面维持圆桌，手机使用双侧席位和可收起的底部手牌。聊天复用公聊抽屉及 VisualViewport 键盘避让。

## 3216 回退

- 事前基线为 Git `269574d`。旧静态构建及 SQLite WAL 一致性备份位于 `work/logs/p20-8-rollback`。备份与隔离演练副本均通过完整性检查，保留原进行中房间。
- 回退前先用 SQLite online backup 保存当时数据库，然后通过 `ninja-p20.cmd stop` 只停止 3216。用独立的 `269574d` 检出运行旧服务，指向备份目录的旧静态构建和原 3216 数据库，沿用原 Cookie 名、端口和来源。先在隔离数据库副本上验证旧服务。
- 本次不迁移结构。先用原数据库回退代码，只有确认需要撤销更新后数据且获得授权时才从备份恢复。恢复时须停止使用该库的进程并按 SQLite 备份流程操作。

## 实体手机验收

3216 绑定电脑回环地址。可用 Android USB 调试在同一台电脑执行 `adb reverse tcp:3216 tcp:3216`，随后在手机浏览器打开 `http://127.0.0.1:3216`。结束后可执行 `adb reverse --remove tcp:3216`。不修改 FRP 或服务器监听地址。iOS 需要另行提供经授权的 HTTPS 测试入口。

1. 用手机登录 3216，同三名独立账户建房开局。
2. 竖屏完成轮抽、目标选择、手牌收起及展开、确认、刺杀反应和轮末结算，至少打完一场并核对战绩。
3. 在回合中打开聊天和键盘，发送消息；用系统返回键先关聊天或身份弹窗，再返回大厅。验证席位仍存在。
4. 另开标签页确认只读、接管操作并验证旧标签失权。刷新接管页继续比赛。
5. 切换横屏后返回竖屏，打开历史和私人情报，检查滚动、按钮位置和安全区域。
