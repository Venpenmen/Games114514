# Games114514 机制反馈与结算演出规范 v1.0

> 适用范围：所有已经发布、正在开发和未来新增的游戏插件（网页及后续客户端）。本规范约束**反馈的清晰度、节奏、可信性和权限**，不统一画风、字体、背景、角色、材质、音色或故事表达。
>
> 核心约定：**机制优先、焦点明确、结算可见**。
>
> 当前落地：Game 01《诡吹灯》及 Game 02《骰子狼人杀》；Game 03《忍者之夜》目前仅作为未来适配示例，本阶段不修改其代码或美术。

## 1. 不变原则

1. 玩家应能快速回答：**现在轮到谁/什么？哪一个对象正在执行？执行了什么？结果怎样？** 在规则允许的范围内清楚呈现。
2. 把「自己选中」「已经提交」「服务端正在处理」「公开结果」「持续状态」「整局终局」区分开，不得用同一种红光混淆。
3. 公共演出仅使用已公开的服务端事实；私人技能、身份、选择、奖励分值仅展示给授权玩家。不得根据客户端猜测生成所谓的公开因果。
4. 游戏状态和截止时间始终由服务端决定；演出不能阻塞提交、推迟阶段、强制打断倒计时，也不能改变胜负。
5. **一个主要焦点，多个并发目标作为一个结算组**。例如多点数同时处决，不能误演为先后独立裁决。
6. 即使跳过动画、减少动态效果、刷新或掉线恢复，玩家仍能看到准确、可复查的状态与必要文本结果。

## 2. 反馈层级

| 等级 | 场景 | 表达 | 参考时长 | 规则 |
|---|---|---|---|---|
| L1 选择/提交 | 点击卡片、选目标、确认行动 | 明确描边/底色、已提交文字，轻微形变 | 100–200ms | 不弹窗、不泄漏秘密选择 |
| L2 执行焦点 | 正在处理某颗骰子/某张牌/某个合法目标 | 底色聚焦、局部抬升、聚光 | 250–500ms | 一次突出一个主焦点 |
| L3 结算结果 | 生命变化、蜡烛变化、死亡、公开票数、荣誉变化 | 明显状态颜色、数值浮层、短动画+文字 | 500–900ms | 区分「待处决」与「已处决」 |
| L4 终局/重大节点 | 一局胜负、派系奖励、比赛冠军 | 结果面板/弹窗、完整摘要、可复查入口 | 按玩法设定 | 弹窗不能遮挡必须响应的合法限时选择 |

时长仅为建议；同一游戏内高频结果快、稀有重大事件可慢。所有动画采用不依赖颜色的文字/图形双重表达，控制闪烁和连续放大。

## 3. 游戏风格独立性

- 《诡吹灯》：黑暗、火焰、冷暖光、灰烬；点亮偏暖金，摧毁偏暗红/灰白。
- 《骰子狼人杀》：西部酒馆、金属和木质赌桌、骰子跳动、票数聚集；危险、待处决、已处决有明显区别。
- 《忍者之夜》（未来）：纸牌、卷轴、忍术、剪影、秘令和反应窗口。严格先统一亮牌再按编号执行，刺杀反应先于本次攻击结果；单人秘密获知不得公开播放。
- 其他游戏：自定义外观资源、颜色与动画表达，但必须覆盖本规范的状态语义、可用性与隐私约束。平台不硬编码具体插件的角色、骰子或蜡烛规则。

## 4. 交互、性能与无障碍

- 移动端 320px 起确保主目标和按钮仍易点击；浮层、焦点框和动画不应遮挡关键操作、聊天入口、倒计时与虚拟键盘。
- 频繁变化优先局部 CSS transform/opacity 动画，避免整页布局移动，慎用反复全屏弹窗；不强制滚动页面到焦点。
- 尊重 `prefers-reduced-motion: reduce`：去掉放大/摇晃/闪烁，保留清晰背景、轮廓和文字。演出音效服从用户原有静音设置。
- 用户能查看最新结果和历史，不依赖动画本身才能理解发生了什么。弹窗保留可关闭、可键盘操作和焦点恢复能力。
- 多客户端更新可能连跳阶段；新客户端重连只能还原**真实最新状态**，默认不播放并不存在的历史动作。

## 5. 状态事件来源与升级路径

当前已有游戏可直接由已公开的 `last`、`ballots`、`executions`、`summary` 渲染**最近一次**公开结果，刷新后显示文本状态而不是伪造刚发生动画。

今后若要确保每一个快速连续结算都不丢失，需要由对应游戏插件输出正式的结算事件（不要求所有游戏同一种动画），建议字段：

- `eventId` / `matchId` / `phase` / `sequence`：顺序、去重、恢复。
- `kind`、`targets`、`publicPayload`：合法公开结果。
- `visibility` / `recipients`：服务器授权投影；客户端绝不能只靠 CSS 隐藏私人数据。
- `groupId`：同批次多目标同时生效，禁止逐项演出误导。
- `resultText`：可检索、可读的结果摘要。

事件序列须与服务端裁决一致，并有可靠序号或时间标识；刷新、重连时避免无故重播。事件队列不能阻挡服务器继续运行，客户端可快进跳过过期动画。此项是后续架构扩展提议，**本版不更改网络协议或规则引擎**。

## 6. 当前游戏专项验收清单

### 《诡吹灯》
- 被选中的蜡烛具备明显选中状态；提交后不可继续点选。
- 当夜公开结算后仅聚焦**最终改变的蜡烛**，点亮/摧毁效果明确；不得展示三人的秘密选择或操作因果。
- 公开票型能看出是否有人被有效指认，无法达成一致也有文字结果；胜负弹窗保持优先级。
- 三人同选、诡异同烛选择摧毁的规则不变。

### 《骰子狼人杀》
- 当前报数骰子突出；最近已公开的生命变化能明确关联到对应点数，显示正负变化与结算后的生命值。
- 达 `-5` 为「待处决」，只能在完整轮次结束时正式处决；不能把阈值提示当作死亡。
- 投票结束公开目标/无多数；由投票、生命值或庄家清场触发的实际处决突出展示，多个同时目标统一表示。
- 普通终局、同点特殊终局、加赛、冠军保持现有服务端规则；不能显示其他玩家未公开的身份。

### 新插件
- 先列明所有关键目标及其生命周期、公开/私人事件、特殊反应与同时结算情况，再选择符合自身美术风格的 L1–L4 表现。
- 《忍者之夜》在美术实施前必须先核实牌编号、荣誉池等仍待确认规则事实；本规范不代替规则冻结及信息权限审查。

## 7. 交付与回归

新增或修改游戏应同时验收：普通提交/超时、连跳阶段、断线重连、延迟消息、历史查看、两种胜负、多目标事件、手机与桌面、减少动态效果、消息/规则/结算弹窗冲突、隐私投影。测试报告区分单元、浏览器隔离环境、正式本机和真实公网，不能以静态截图代替联机验证。
